## Что именно найдено в источнике

Зафиксирована ревизия [desktop-fly 32b0001](https://github.com/DenisSergeevitch/desktop-fly/tree/32b00011e83c3dc85fa3ea0b3934155b04f1635d). Это исходный женский FlyWire circuit; новый MaleCNS-граф на 1045 нейронов не используется.

[data/circuit.json](https://github.com/DenisSergeevitch/desktop-fly/blob/32b00011e83c3dc85fa3ea0b3934155b04f1635d/data/circuit.json) содержит:

```json
{"neurons": [{"id":"FlyWire root ID as string", "type":"LC4", "role":"lc4", "side":"left", "pos":[0,0,0]}],
 "edges": [[0,1,12.0]]}
```

Выше показана только схема, не реальные значения первой строки. `edges` = `[preIndex, postIndex, signedSynCount]`; индексы нулевые, адресуют порядок `neurons`. ID — большие строковые FlyWire root IDs, их нельзя превращать в индексы или хранить в float. `pos` — нормализованная анатомическая позиция нейрона, не позиция мухи в игровом мире.

В данных **668 нейронов, 18 968 строк связей: 11 171 положительных и 7797 отрицательных**. Строка — направленная связь с числом контактов, а не один физический синапс; повторные пары нельзя произвольно удалять. [etl.py](https://github.com/DenisSergeevitch/desktop-fly/blob/32b00011e83c3dc85fa3ea0b3934155b04f1635d/etl.py) задаёт `NT_SIGN`: ACH +1; GABA/GLUT −1; DA/SER/OCT +0.5; неизвестный тип +1 с учётом в отчёте. В compact JSON уже сохранён подписанный вес; точный исходный нейромедиатор по одному знаку восстановить нельзя.

В [Sim.swift](https://github.com/DenisSergeevitch/desktop-fly/blob/32b00011e83c3dc85fa3ea0b3934155b04f1635d/Sim.swift) искать `CircuitNeuronFile`, `CircuitFile`, `LIFSim.init`, `step`. Эквивалент на JS — [windows/src/sim.js](https://github.com/DenisSergeevitch/desktop-fly/blob/32b00011e83c3dc85fa3ea0b3934155b04f1635d/windows/src/sim.js), класс `LIFSim`, конструктор и `step(ms)`.

## Воспроизводимый экспорт

Из корня UE-проекта, Python 3 со стандартной библиотекой и Git:

```powershell
git clone https://github.com/DenisSergeevitch/desktop-fly.git ../desktop-fly-reference
git -C ../desktop-fly-reference checkout 32b00011e83c3dc85fa3ea0b3934155b04f1635d
python Scripts/export_fly_connectome.py ../desktop-fly-reference
```

На текущем ПК clone уже находится в `E:/Game/desktop-fly-reference`; повторно клонировать его не требуется. Экспортёр проверяет ревизию, размер графа, уникальность ID, допустимость индексов/весов, затем строит CSR:

1. `RowStart[669]` — начала исходящих рёбер каждого нейрона.
2. `Targets[18968]` — `uint16`-индексы целей.
3. `Weights[18968]` — `float`: `signedSynCount * 0.0008`.
4. Для LC4/LPLC2 → GF и other/sensory → GF применяется source multiplier 6. Это модельная аппроксимация electrical coupling, не дополнительное измерение анатомии.
5. `Role`, `SensorSide`, `GroupCount`, `Baseline` и списки групп экспортируются рядом. Порядок рёбер внутри каждого presynaptic row сохраняется.

Сгенерированный файл включён только в `FlySwarmMob.cpp`. `FFlyConnectome::Get()` возвращает одну `static const` структуру с указателями на эти массивы. Ни экземпляры актора, ни мухи не создают копию графа. Разные процессы Host/Client имеют собственные адресные пространства; сервер симулирует SNN, клиентские мухи не выделяют SNN state.

Для переноса в другой UE-модуль скопировать `.h`, `.cpp`, `.inl`, заменить `CALMYPIRATESCO_API` своим export macro, сохранить путь include либо изменить его. В Build.cs нужны `Core`, `CoreUObject`, `Engine` — здесь они уже присутствуют. JSON не загружается в runtime: не нужны JsonUtilities, поиск файлов на диске и дополнительный cook JSON. Исходный JSON, манифест, генератор и лицензии следует хранить для воспроизводимости.

## LIF и время

Один нейронный шаг равен **1 мс**. Для нерефрактерного нейрона:

```text
V = 0.9512 * V + baseline + (random < 0.0022 ? 0.42 : 0)
V += sensory input (LC4/LPLC2 left or right)
V = max(-2, V + inhibition arriving from t-4 ms), if present
if refractory == 0 and V >= 1:
    V = 0
    refractory = 2 ms
```

`0.9512 ≈ exp(-1/20)`: τ около 20 мс; потенциал и current kick нормализованные, не измеренные mV/pA. В рефрактерности таймер уменьшается на 1 мс и V затухает без baseline/noise; сенсорная и синаптическая инъекция всё равно возможна, как в источнике. На шаге достижения refr=0 снова разрешён spike.

Сначала определяются **все** спайки, потом распространяются положительные веса. Получатель проверяет порог на следующем шаге — нет каскада, зависящего от порядка обхода нейронов. Отрицательные веса доставляются через 4 мс. Затем вычисляется EMA Hz/neuron с `alpha=1/120` на каждом 1-мс шаге, GF latch сохраняется до моторного чтения.

`FTimerManager` вызывает весь рой на game thread с частотой 20–30 Гц, по умолчанию 25. Один callback = 40 подшагов при 25 Гц или 50 при 20; при 30 Гц остаток даёт 33/33/34, без потери дробных миллисекунд. Actor Tick отключён. Нейронный шаг нельзя менять на 40 мс при прежних константах. Таймер зависит от игрового времени, уважает pause/time dilation и при медленном кадре догоняет фиксированные интервалы. Это не отдельный realtime-поток; длительный stall может вызвать дорогой catch-up.

## Память, производительность, предел точности модели

На муху: `float V[668]`, `uint8 refractory[668]` и 5 битовых масок спайков, всего **420 байт** для задержки. Только V/refractory недостаточно для исходной модели: без истории невозможно воспроизвести отложенное торможение. История заменяет исходную очередь из `5*668 float` (13 360 байт), восстанавливая ток по общему графу. Временный буфер суммы inhibition и список текущих спайков выделены на стеке вызова и переиспользуются обработкой мух на рабочих потоках (отдельный scratch каждого одновременного вызова). Дополнительно — девять rates, RNG, часы/latch, координаты/скорость/yaw/время escape. На Win64 automation измерил `sizeof(FFlyLIFState)=3816`, `sizeof(FFlyAgentState)=3872`: 200 агентов занимают 774 400 байт (~0,74 MiB), дополнительно хранятся HISM transforms и сетевые poses. Основные неизменяемые массивы графа — около 118 KiB на процесс.

На каждом шаге обновляются все потенциалы; CSR-рёбра обходятся только у текущих и отложенных спайков. 200 мух означают 133,6 млн нейронных обновлений в секунду плюс активные рёбра. Реальная стоимость зависит от CPU и стимуляции; 25-Гц таймер сам по себе не снижает частоту LIF. Независимые мухи обрабатываются синхронным `ParallelFor` с batch size 8. Перед запуском на game thread копируются параметры/координаты угроз; workers читают только plain data и пишут собственные state/pose. Join завершается до обращения к HISM/репликации; нет фоновых задач, переживающих актор. Все transforms отправляются одним batch-update на callback; HISM spatial tree при постоянном движении также имеет стоимость. Mesh с большим числом треугольников ухудшит графический результат независимо от SNN.

Отличия от полной desktop-fly: heterogeneous baseline заморожен детерминированным seed 783 в общем графе, а не генерируется заново на каждую муху; независимы noise RNG и динамическое состояние. Нет редких arousal bursts, циркадного/sleep/thermal слоя, air-puff и gait feedback, click stimulation, MaleCNS/мышц, анимации ног. Группы sensory/ascending сохранены для будущего расширения. Не заявляется физиологически точная симуляция живой мухи.

## Размещение и параметры редактора

1. Собрать `CalmyPiratesCoEditor` и создать Blueprint с родителем **FlySwarmMob**, либо перетащить C++-актор в уровень. Construction preview показывает стартовый рой.
2. В `Fly Swarm → Fly Mesh` назначить любой `Static Mesh`. Пока используется маленькая sphere как placeholder. Mesh должен смотреть вдоль локальной +X, верх +Z; скорректировать asset orientation при импорте. `Mesh Scale=0.06` настроить под реальные размеры выбранного меша.
3. Поставить актор в центр свободного воздушного пространства; рекомендуемый actor scale `(1,1,1)`. Позиции runtime мировые, transforms конвертируются в локальные для HISM. `Spawn Radius=180 cm` задаёт начальный объём, `Roam Radius=600 cm` — игровое ограничение удаления от центра. Runtime spawn radius не превышает roam radius.
4. Начать с `Fly Count=50`, `Simulation Hz=25`. Поддерживается 20–200, в C++ значения дополнительно ограничены. Count/Hz/seed выбираются до BeginPlay; после изменения в редакторе перезапустить PIE.
5. `Danger Radius=500 cm` измеряется отдельно для каждой мухи до ближайшего possessed player pawn либо actor из `Danger Sources`. Для триггера поместить `TargetPoint`/другой actor и добавить в список. Учитывается позиция актора, не размеры его collision volume; активный список можно менять на сервере через Blueprint.
6. `Sensory Gain=0.30` — исходная нормализованная прибавка за 1 мс. Стимул плавно растёт от 0 на границе danger radius до 1 у угрозы, распределяется между левым и правым loom-входом по положению угрозы относительно yaw.
7. `Cruise Speed=100 cm/s`, `Escape Speed=320 cm/s`, `Max Turn Rate=180 deg/s`. DNp09 Hz задаёт обычную скорость, MDN может включить обратное движение, разница DNaR−DNaL задаёт yaw. GF spike включает 0,45-секундный escape с поворотом от опасности и набором высоты; затем муха возвращается к высоте центра. Heading-away и удержание в roam sphere — явно игровые контроллеры поверх SNN. Groom/Wing rates сейчас не управляют анимацией.
8. В multiplayer актор создаётся **на сервере**. Сервер ищет pawns всех player controllers; клиент только получает текущие quantized positions/yaw/mesh/scale и обновляет HISM. Late join сразу получает текущий рой. Нет RPC. `bAlwaysRelevant` выбран для небольшого числа роёв; сетевой бюджет многих роёв требует отдельного профилирования.

Collision, урон/HP, навигация вокруг стен, материалы крыльев и звук этим актором не реализованы. Рой удерживается в сфере, но может пересекать геометрию уровня. Не расставлен автоматически на WaterLab/OceanFreighterR7; существующие `.umap` не менялись. Это готовый программный актор с placeholder mesh, а не завершённый художественный enemy asset.
