# Подготовка инструментов — 2026-09-09

Запрос: догрузить ранее предложенные инструменты. Результат: необходимые локальные компоненты уже установлены; загрузок новых пакетов не было. Включён Rigify, проверены действующие мосты. Это настройка среды, не новый персонаж/импорт/игровая сборка.

## Что выполнено

- Blender 5.2.1 LTS: bundled `rigify` был доступен, но выключен. Включён с сохранением preferences; проверена генерация disposable human metarig → rig (706 управляющих/deform/mechanism bones суммарно). Это не готовый игровой скелет и не рекомендация экспортировать все 706 костей.
- [setup_blender_rigify.py](../../Scripts/setup_blender_rigify.py) повторяет настройку в отдельном background Blender. Не сохраняет `.blend` модели; сохраняет только пользовательские preferences. До изменения создаёт датированную копию `userpref.blend` рядом с оригиналом.
- Копия этого запуска: `userpref.before-rigify-20260909-221601-951781.blend` в пользовательском Blender 5.2 `config`. Для отката закрыть Blender и восстановить эту копию в `userpref.blend`. Это локальные настройки вне переносимого репозитория.
- Blender MCP: запущен обычный Blender с пустой сценой, без открытия/перезаписи R8 или судна. Через MCP подтверждены Rigify `[true,true]`, версия Blender 5.2.1 LTS и отсутствие открытого файла.
- Addon status: `up_to_date=true`, protocol 5 / expected 5, addon version 1.6, telemetry consent false. Номер addon не равен версии Python-пакета; установленный addon признан совместимым сервером. Переустановка не нужна.
- Unreal Editor 5.8.2 открыт на WaterLab. MCP initialize → initialized → tools/list PASS; negotiated protocol `2025-11-25`, три discovery tools: list_toolsets, describe_toolset, call_tool. Первый ручной probe ошибочно сохранил старый protocol header и получил отказ; повторный script берёт версию из ответа initialize.
- [test_unreal_mcp.ps1](../../Scripts/test_unreal_mcp.ps1) — read-only протокольная проверка, не выполняет инструменты и не изменяет карту; закрывает собственную MCP-сессию.
- [start_dev.ps1](../../Scripts/start_dev.ps1) теперь явно включает MCP для запуска Editor, задаёт loopback HTTP bind, проверяет конфликт портов и по умолчанию запускает служебные окна скрытыми. `-ShowWindows` — видимый запуск новых окон для работы пользователя. Уже открытые пользовательские редакторы не закрывает/не заменяет.
- Подтверждены listeners **127.0.0.1:8000** (Unreal) и **127.0.0.1:9876** (Blender). Firewall не менялся. Прямой Blender MCP вызов доступен в задаче; Unreal проверен через локальный HTTP. Появление native Unreal tools в текущем клиенте отдельно не подтверждено — может потребоваться переподключение MCP клиента.
- Git LFS 3.3.0, clean/smudge/process filters и pre-push hook уже существуют. Ничего не переустанавливал, hooks не перезаписывал, файлы не добавлял в Git.
- Навык Plugin Management найден в установленной папке версии **0.1.0**. Предыдущее предположение об отсутствующем навыке было следствием проверки неправильного пути 1.0.0; ремонт не требуется.

## Как запускать дальше

Из корня проекта в PowerShell:

```powershell
./Scripts/start_dev.ps1 -ShowWindows
./Scripts/test_unreal_mcp.ps1
```

Без `-ShowWindows` новые процессы скрыты. Скрипт не выводит уже скрытые окна на экран. Blender запускается без проектного файла: нужный master открыть отдельно после проверки несохранённой работы. Сервер Blender не работает в `--background`; CLI остаётся вариантом для изолированных batch-тестов. На другом ПК передать `-Editor` и `-Blender` с местными путями. Autostart после перезагрузки ОС не создавался.
