## Принцип доводки

Корабль — основное пространство игры, а не дальняя декорация. Приоритет: проходимость и доступ к задачам → качество на расстоянии рук → завершение всех помещений → внешние детали → интеграция/оптимизация. Пустые нижние палубы не считаются завершёнными из-за красивой надстройки.

Вести статус каждой зоны отдельно по четырём осям: геометрия, арт/материалы, игровой доступ, проверка в Unreal. Вместо вычисленного процента использовать «набросок / рабочая / проверенная / принята пользователем».

## S1 — проходимость в условиях игры

Существующую лабораторию разрешено использовать без замены основной игровой карты. Не ограничиваться лучом или teleport-to-waypoint: нужен CharacterMovement и проверка фактического прохождения.

- [ ] Повторить обязательные маршруты текущим Deckhand с bodycam. Проверить обе стороны каждого перехода, повороты, остановки и восстановление после падения.
- [ ] Для главных рабочих путей: пустые руки, обычный ящик, Bulky с помощником, два встречных игрока. Измерять не только капсулу 34/88 см, но и груз, конечности и обзор.
- [ ] Проверить дверь → площадка → первый/последний шаг лестницы → следующий уровень; перила не должны разрывать маршрут или направлять в пустоту.
- [ ] Пройти непрерывные сценарии: каюта → мостик; мостик → палуба → трюм; камбуз → жилая зона; рабочая палуба → машинное → насосы → кормовой вал; нос → кормовая площадка.
- [ ] Проверить доступ к каждому обслуживаемому прибору/шкафу/насосу. Обход комнаты не доказывает, что персонаж может занять рабочую позицию.
- [ ] Контрольные негативные тесты должны действительно ловить препятствие, отсутствие пола и слишком узкий проход; сохранять контактные meshes и координаты остановки.

Приёмка: все обязательные игровые маршруты в обе стороны проходят без прыжка через дефект, телепорта или отключения коллизии. Каждый оставшийся контакт объяснён. Удерживаемый груз не проходит через закрытую дверь/стену ради зелёного теста.

## S2 — два эталона до массового наполнения

Довести небольшой участок машинного отделения и одну каюту с частью коридора. Для каждого: общий вид, уровень глаз, крупные планы соединений и реальный маршрут. Утвердить качество у пользователя; затем распространять модульный стандарт.

- [ ] Машинный эталон: узнаваемая сборка, фланцы/крепёж/опоры, точки обслуживания, трубные связи, маркировка, свет, умеренный износ и свободная рабочая площадка.
- [ ] Жилой эталон: законченная мебель, матрас/постель, шкаф/ручки, рабочий свет, судовые фиксаторы и индивидуальные бытовые детали. Не загромождать пол случайным реквизитом.
- [ ] Материалы: масштаб фактуры, UV/плотность, roughness/metalness, фаски и нормали; одинаковый материал должен выглядеть одинаково в соседних помещениях.
- [ ] Зафиксировать язык стилизации: современный промышленный корабль, читаемые формы и умеренная комедийность, а не смешение фотореальных покупных деталей с примитивами.

Приёмка: пользователь принимает качество двух зон с близкого расстояния. Без этого массовое копирование мебели и приборов откладывается.

## S3 — покомнатная доводка всего судна

Порядок ниже — стартовый; после playtest его уточняет частота реальных маршрутов. Каждая строка проходит собственный цикл «проверка → правка → крупные кадры → физический проход → запись результата».

| Зона | Работы | Особая проверка |
|---|---|---|
| Tank top / нижнее машинное | Фундаменты, насосы, трубопроводы, клапаны, дренаж, доступ к обслуживанию | Рабочие позиции, высота под трубами, эвакуация с двух сторон |
| Машинное / tween | Двигатель, генераторы, теплообменники, щиты, инструмент, площадки и кабели | Кормовые crosswalk R6, обход агрегатов, груз/помощник, свет аварийного режима |
| Кормовой вал / рулевое | Последовательная компоновка вала, опор и рулевого оборудования | Доступ не пересекает механизмы; снаружи отдельный крупный обзор винта и руля |
| Носовое служебное | Thruster, опоры и сервисное оснащение, цепные/якорные узлы | Апрон перед дверью, проход не через мотор; доступ к оборудованию |
| Оба трюма / нижние палубы | Конструктивные детали, лестницы/ограждения, свет, крепления груза, служебные зоны | Реальный грузовой маршрут; отличать пустую грузовую ёмкость от незаконченной комнаты |
| Weather deck | Люковые крышки, лебёдки/брашпиль, кнехты, клюзы, цепи, вентиляция, пожарные точки | Все предметы закреплены; цепь не набор разорванных цилиндров; непрерывные боковые пути |
| Краны / шлюпки / наружные лестницы | Осмысленные механические узлы, тросы/блоки, крюки, опоры шлюпок, крепёж и площадки | Не перекрывать пути; никакой декоративной лестницы без выхода на уровень |
| Crew / officers | Различимые каюты, шкафы, постели, личные вещи, свет, коридорные указатели | Доступ к кровати/столу/шкафу; мебель не закрывает дверь |
| Mess / galley / laundry / sanitary | Оборудование по назначению, сантехника, вытяжки, фиксаторы, хранение | Проходы и рабочие зоны, отсутствие случайных пересечений |
| Medical / radio | Довести уже добавленные модели, мелкие принадлежности, приборы/проводку | Сохранить доступ к койке/тележке и рабочей позиции оператора |
| Bridge / roof | Консоли, органы управления, приборы, кресла, проводка, антенны/радарные крепления | Обзор изнутри, подходы, мостик → наружный трап; без маскировки проблем cutaway |
| Корпус / наружная надстройка | Стыки, окна/двери, вентиляция, материалы, маркировка, осмысленный износ | Палуба не выходит за корпус; нет лишних нижних ограждений/висящих деталей |

Ассеты: сначала использовать/улучшать существующие модули. Если не хватает конкретного предмета, искать только под его роль и масштаб; сохранять URL, автора, лицензию, право коммерческого использования и условия атрибуции. Платные покупки согласовывать. Проверять полигоны, UV, материалы, коллизии и стилистику до распространения по кораблю.

## S4 — подготовка к Unreal без преждевременного импорта

- [ ] Стабильные имена, метры/сантиметры, transform/pivot, разбиение по зонам и назначению. Разделить неподвижную конструкцию, физические предметы и игровые механизмы.
- [ ] UV, корректные нормали, отсутствие дубликатов/z-fighting, библиотека материалов; все внешние ассеты включены в реестр происхождения.
- [ ] Production-коллизия для ходьбы и переносимых объектов; не считать per-triangle лабораторную проверку достаточной для движущегося судна.
- [ ] Стратегия LOD/инстансинга/видимости и бюджет материалов/памяти по измерениям. Не назначать весь корабль Nanite или единым rigid body автоматически.
- [ ] Экспорт в отдельный кандидат: manifest версии, hash master, список meshes/materials/collision, воспроизводимая сборка и регрессия маршрутов после каждого изменения.

Приёмка: подготовлен воспроизводимый пакет; нет потерянных материалов, неверного масштаба или исчезнувших проходов. Финальная производительность в игре проверяется в S5/S6, а не объявляется по Blender-рендеру.

## S5 / G5 — интеграция только после разрешения

Вход: S4 и успешный G4, включающий результаты движущегося proxy из G2. Пользователь отдельно разрешает добавить судно.

Сначала импортировать статический кандидат в отдельную review-карту; проверить тело/камеру/груз, освещение и отсечения. Затем привязать реальные игровые точки и аварии к помещениям. Только после этого применить доказанную модель движения/воды. Замена WaterLab как стартовой карты — отдельное явно принятое решение.

## S6 — общая приёмка и правило частых крупных кадров

- [ ] Для каждой зоны: общий кадр + уровень глаз + крупные планы оборудования, дверей/лестниц, стыков потолка/пола. Для каждой правки — до/после с тем же ракурсом и hash модели.
- [ ] Кадры в закрытом интерьере без скрытия мешающих стен/крыши; отдельно нормальный игровой и аварийный свет. Технический cutaway допустим только как дополнительная диагностика.
- [ ] Видео непрерывного обхода всех уровней; не заменять его монтажом удачных локальных проходов.
- [ ] Обход с грузом/помощником и четыре участника в узких местах, падение/восстановление, камера у стен, сетевые коррекции.
- [ ] Проверка производительности в машинном, жилом коридоре, мостике и на длинном палубном виде с полной игровой нагрузкой.
- [ ] Свободный пользовательский обход: ошибки фиксируются с координатой/зоной и получают повторный тест после исправления.

Приёмка целого судна: все зоны учтены и закончены по согласованному стандарту, обязательные маршруты работают, открытые визуальные/физические блокеры отсутствуют, производительность измерена, пользователь принял корабль. Набор зелёных тестов сам по себе этого статуса не даёт.

## Ближайший корабельный спринт и контрольная точка «30%»

При ограничении недели не обещать полную отделку 122 м и всех внутренних палуб. Последовательность: S0 → критические S1 → два эталона S2 → пользовательский обход в конце. Этот объём конкурирует за время с [игровым спринтом](../../GAME_ROADMAP.md), а не добавляется к нему бесплатно.

К показу подготовить:

1. Реестр всех помещений и классификацию 43 исследовательских отказов.
2. Исправленные новые блокеры и повторные тесты текущего героя на главных непрерывных маршрутах.
3. Две заметно законченные зоны: машинная и жилая, с крупными кадрами и видео.
4. Список «сделано / проверено / осталось», без объявления оставшихся простых помещений готовыми.
5. Отдельную сцену/инструкцию для самостоятельного обхода; основную игру и её карту не менять.

Пользователь после этого решает, соответствует ли результат 30%. Если нет — следующий цикл закрывает конкретные замечания, а не увеличивает формальный процент.
